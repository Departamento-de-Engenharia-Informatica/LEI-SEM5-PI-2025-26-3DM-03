# User Story 3.5.2 - Network Access Restriction
### Systems Administration & Security
---

## 1. Overview
**User Story 3.5.2**  
*As a System Administrator, I want access to the solution to be restricted to clients connected to the DEI internal network (wired or via VPN), so that the system remains secure and compliant with institutional access policies.*

Applies to all environments in the current implementation (dev, staging, and production). Goal: only approved IPs reach the backend and Swagger.

---

## 2. Objectives
- Allow only DEI internal IPs (wired or VPN)
- Keep authentication via external IAM; authorize by network via middleware
- Block and log external attempts
- Keep safe localhost exception in Development
- Centralize CIDR ranges in a simple file

---

## 3. Solution Architecture
- Custom `NetworkRestrictionMiddleware` placed before Swagger and the rest of the pipeline.
- File `allowed_ips.txt` resolved from the process working directory (project root in this repo: `TodoApi/allowed_ips.txt`) with CIDR blocks.
- Dynamic reload with `FileSystemWatcher` (no service restart).
- Path uses the process working directory; package includes the file so it is available alongside the app.

### Flow
1. Load CIDR ranges into `IPNetwork`.
2. Check `RemoteIpAddress` on each request.
3. Development: `127.0.0.1` and `::1` always allowed.
4. Outside the allowlist: returns `403` and logs the block.

---

## 4. Allowed Ranges (allowed_ips.txt)
```
193.136.0.0/16
193.137.0.0/16
```
- DEI wired, VPN, and lab subnets.
- Format: one CIDR per line; blank lines ignored.

---

## 5. Pipeline Integration
`Program.cs` (active in all environments):
```
app.UseMiddleware<NetworkRestrictionMiddleware>();
app.UseSwagger();
app.UseSwaggerUI();
```
Placed early to protect Swagger and APIs.

---

## 6. Logging and Errors
- Missing file: `[WARNING] allowed_ips.txt not found - denying all requests`
- Invalid CIDR: `[ERROR] Invalid CIDR entry: "<value>"`
- Locked file: `[ERROR] Could not reload allowed_ips.txt - file is locked.`
- External attempt: `[ACCESS BLOCKED] IP <ip> tried to access on <timestamp>.`

---

## 7. Tests Performed
- With DEI VPN: access OK (Swagger and APIs).
- Outside ranges / no VPN: 403 with "Access restricted to DEI internal network."
- Modify `allowed_ips.txt` and save: ranges update without restart.
- Add invalid line: entry ignored and error logged; remaining ranges active.

---

## 8. Acceptance Criteria Mapping
| Acceptance Criterion | Evidence |
|----------------------|----------|
| Access restricted to internal network | Middleware + CIDR allowlist |
| External IAM kept; authorization by network | Middleware runs before business logic |
| External attempts logged and denied | Block logs + 403 |
| Applies to dev and staging | Middleware active in dev/staging (and currently also production); localhost exception only in Development |

---

## 9. Conclusion
Solution satisfies US 3.5.2: network-based restriction with centralized list, audit logs, and dynamic reload, protecting even Swagger.
