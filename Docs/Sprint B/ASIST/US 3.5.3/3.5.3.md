# User Story 3.5.3 - Allowlist Configuration
### Systems Administration & Security
---

## 1. Overview
**User Story 3.5.3**  
*As a System Administrator, I want the list of allowed client endpoints (as defined in US 3.5.2) to be configurable by editing a simple text or configuration file, so that access control remains easy to maintain without redeployment.*

Focus: simple allowlist file, immediate application of changes, and detection of invalid configuration. Middleware currently runs in all environments (dev, staging, and production).

---

## 2. Objectives
- Simple, well-documented file to manage the allowlist
- Changes become active without restart (hot reload)
- Validate format and log errors for invalid entries

---

## 3. File Format (allowed_ips.txt)
- Location: process working directory (in this repo: `TodoApi/allowed_ips.txt`, copied next to the app).
- Syntax: one IPv4 CIDR per line; blank lines ignored.
- Example:
```
193.136.0.0/16
193.137.0.0/16
172.16.0.0/12
10.0.0.0/8
```

---

## 4. Hot Reload (No Restart)
- `FileSystemWatcher` monitors `allowed_ips.txt` with 200 ms debounce.
- Changes apply immediately (no redeploy).
- Path uses the process working directory; file is packaged with the app so it is available in service/container.

---

## 5. Invalid Configuration Handling
- Invalid line: `[ERROR] Invalid CIDR entry: "<value>"` (line discarded; others kept).
- Missing file: `[WARNING] allowed_ips.txt not found - denying all requests` (empty allowlist blocks all).
- Locked file: `[ERROR] Could not reload allowed_ips.txt - file is locked.` (keeps previous config).

---

## 6. Pipeline Integration
`Program.cs` (middleware active in all environments):
```
app.UseMiddleware<NetworkRestrictionMiddleware>();
app.UseSwagger();
app.UseSwaggerUI();
```
Dynamic allowlist used by middleware on all requests (Swagger included). Localhost only allowed in Development.

---

## 7. Tests Performed
- Add new network to the file: requests from that network pass without restart.
- Remove a network and save: IP gets 403.
- Insert invalid line: error logged; other ranges remain active.

---

## 8. Acceptance Criteria Mapping
| Acceptance Criterion | Evidence |
|----------------------|----------|
| Simple, well-documented format | Text file with CIDR per line + format section |
| Changes without restart | FileSystemWatcher + 200 ms debounce |
| Invalid config detected and logged | Error/warning logs for invalid CIDR or missing file |
| Availability across envs | Middleware uses the allowlist in dev/staging/production (localhost exempt only in Development) |

---

## 9. Conclusion
Allowlist is managed via a simple file with immediate reload and error validation, fulfilling the ACs of US 3.5.3 and integrating with the network restriction middleware.
